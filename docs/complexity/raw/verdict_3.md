## repairs

E1/E4 are FUNDAMENTAL to this architecture, not patchable by count/parity/genre tweaks: the forcing is purely flow-based, and the design's own uniformity lemma (MV8: all deviations column-uniform and height-invisible) is what makes the v-algebra compensations free. The author's closing diagnosis is the correct epitaph — skyline column-independence makes 'armed' a locally cheap, reversible, CONCURRENCY-FRIENDLY property, so any repair must make receptivity a globally exclusive resource. Three earlier designs plus the mirror repair all die at the same point; I see no count-based fix. What a real repair needs: a physical exclusivity token — e.g., a unique piece-configuration that must be geometrically DISMANTLED in one bucket before it can be assembled in another, with dismantle+assemble consuming pieces whose global count equals exactly (#boundaries)·cost with zero reroutable surplus, AND with the 6R gate slack eliminated first (O3 must be closed to O(1) before any exact-count argument means anything; otherwise the token accounting drowns in slack). No such primitive is exhibited, and MV11 shows the natural candidates (T-well etc.) are not type-pure, so this needs a genuinely new idea. E2 repairs only by closing O3 (gate redesign to O(1) slack — the author already showed the obvious prefill orientations fail). E3 repairs plausibly by prefilling every well's bottom 4 rows EXCEPT leaving one permanently-unfillable notch per low row outside the gate... but any such notch must itself eventually fill for the terminal clears, recreating the problem — needs design work; alternatively accept early clears and prove a clear-count/cell-budget invariant that is shift-independent (harder but maybe cleaner).
